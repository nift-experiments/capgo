# Metadata recovery

All 1,343 non-redirect heads regenerate in ordinary `nift build` from authored or deterministic inputs. Four compatibility redirects retain their generated refresh/canonical markup. `node tools/verify-heads.mjs` checks every route separately from body parity.

Marketing, product, solution, comparison, tools and legal metadata evaluates the actual authored page/component `Layout.content`, then the actual `SEO.astro`. Blog titles, social images, keywords, author/date metadata and NewsArticle/FAQ structured data evaluate the original `[slug].astro` frontmatter against source frontmatter and source-rendered HTML. The seven MDX blog entries have no `entry.rendered.html` upstream, so their structured-data article body is empty; this confirmed upstream behavior is preserved. Plugin metadata evaluates the original registry/tutorial template, including authored SEO overrides, runtime platform labels, FAQs and SoftwareApplication graphs. Listing metadata comes from the original shared BlogListing frontmatter and human/AI origin.

Docs metadata uses pinned Starlight 0.42.3 `getHead` and schema, followed by Capgo's authored Head override. The default global favicon/title delimiter/format configuration is explicit in `data/starlight-head-provenance.json`; the authored docs config supplies the site title. Frontmatter head overrides, summaries, canonical URLs, description rules and alternate languages are preserved. Bundled dependency source/license and a reproducible bundling command are committed. No Astro build or original checkout is needed during normal rendering.

Shared Nift head templates preserve formatting and compiler resource declarations. `migration/authored-head-sources.json` and `migration/docs-head-sources.json` contain token **roles**, not frozen per-page metadata values. Normal preparation hashes source, code, templates, dependencies and Node version, then writes optional cached intermediates under `build/faithful/metadata`. Missing intermediates regenerate. The earlier `migration/head-metadata.json` is a recovery/audit record; its per-page values are no longer consumed by normal builds.

Generated compiler labels (`Astro v7.3.4`, `Starlight v0.42.3`), stylesheet/module resources and third-party script markup remain production artifacts by design. They describe the preserved upstream implementation, not the Nift generator's version. Reference clocks are explicit build inputs; UTC offer expiry and local display date are separately recorded.

The metadata-only adapter executes reviewed source frontmatter. English content schema inputs are bounded: non-English redirect branches throw rather than render a redirect as metadata. Unregistered imports, missing metadata roles and unexpected roles fail instead of falling back to reference values. This is not an arbitrary Astro application interpreter.
